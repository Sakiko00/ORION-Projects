# 发布流程（NURION）

> 项目在 monorepo `ORION-Projects` 里，本项目的目录 = `nurion/`。
> 这份文件是 NURION 自己的发布规矩，和根 README 的仓库约定一致。

## 铁律

- **只改 `nurion/` 和根 README 里那一行**；提交前 `git status` 自查，看到别的目录被改就停手
- **用分支 + PR，不直接推 main；绝不 force push**
- **标签、分支都带 `nurion-` 前缀**（`nurion/2.0`、`nurion-v2.0.0`），不跟别的项目混

## 每个版本四步

1. 开发：`git checkout -b nurion/2.0`，只动 `nurion/`
2. 合入：提交后开 PR 合回 `main`
3. 打标签：`git tag nurion-v2.0.0`
4. 发版：GitHub Releases → 选该 tag → 把 `NURION-v2.0-测试版.zip` 挂上去

## 打包

- 源码就在 `nurion/`；安装包由根目录 `npm run dist` 产出（`release/` 已被 .gitignore 挡住）
- 内嵌引擎怎么重建见 `resources/engine/README.md`（那份本体 300MB+，**永远不进仓库**）

## 版本号 vs 存放

- 源码：`nurion/` 只放最新版（不拆 `nurion-v2/` 这种文件夹）
- 历史：靠 tag 标到每个版本
- 二进制：只进 GitHub Release 附件
